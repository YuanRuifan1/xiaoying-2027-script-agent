# 复盘与下一步

## 最难的问题：让完成状态有证据

本项目的关键是把“生成了脚本”与“完成了任务”区分开。具体产品主张需要原文支持；脚本修改后，需要重新检查当前版本。实现中用来源映射和脚本哈希关联检查结果，只有最新版本通过两项检查才能返回 completed。

真实运行曾出现模型在调用时长工具前就主动缩短初稿的情况。为使超时修订路径可验证，增加了先观察初稿的前置条件。最终记录展示模型先获得 44 秒反馈，再修订为 26 秒并复查通过。程序负责执行边界，修改内容仍由模型选择。

## 复现推动的改进

本地复现中，免费模型调用出现 HTTP 429。我反馈这一问题，并决定切换付费模型再次验证。GLM-4.7 的正常生成和超时修订均完成，共 11 次请求返回 HTTP 200；先前的失败记录仍保留在仓库中。

这次过程说明，模型接口可用性和业务决策正确性需要分别观察。请求间隔、有界退避和明确的失败状态解决工程可靠性问题；工具反馈后的实际动作变化用来验证 Agent 决策。

测试重点覆盖了过期检查、有效来源 ID 搭配无依据主张、画面停留很短但旁白过长、资料内容变化等问题。把这些边界写成可执行测试，有助于在后续调整模型或提示词时复核结果。

## 当前取舍与学习收获

首版优先保证事实依据和可验证性：产品句逐字引用事实，标题、衔接文案和画面说明采用批准选项。这降低了无依据表述的风险，也限制了自由创作，受众、平台和风格的表现空间仍需扩展。下一步应将产品事实主张与创作表达分开评估，增加批准表达和人工标注用例，再引入语义支持检查，衡量误拒绝和漏检。

当前检索是小规模关键词匹配；时长按固定语速估算，尚未使用真实配音测量。两次付费模型成功记录证明了对应路径的实际执行，后续还需要更多独立输入评估稳定性。

## 下一步

1. 扩充创作表达和不同受众、平台、风格的样例，验证生成质量。
2. 增加检索改写与事实支持判断的评估集。
3. 接入 TTS 或实际配音测量，校准时长估算。
4. 在核心链路和验证充分后增加交互界面。
