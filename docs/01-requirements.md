# 需求、范围和验收

用户是短视频创作者，目标是在产品事实与品牌限制内，得到可编辑且不超预计时长的脚本。交付采用 CLI，不生成视频。产品资料为虚构，不代表小影产品能力。

输入：主题、受众、平台、目标秒数、风格；允许用户提供初稿。输出：标题、分镜、旁白/字幕、逐镜头与总时长、来源 ID 与引用原文、风险和任务状态。

成功标准：真实模型至少经历“选择动作—执行工具—观察结果—继续或结束”的循环；最新脚本通过时长与规则检查；成功状态不能由普通文本绕过。两个检查必须对应当前脚本哈希。没有可用资料、工具故障或超过步数上限时，如实返回相应状态，保存已有结果。

| 题目验收点 | 输入/运行场景 | 验证方式 |
|---|---|---|
| 正常生成 | normal | 完整字段、有效引用、两项检查通过 |
| 缺关键信息 | missing | needs_input，明确缺失字段，不猜测硬性时长 |
| 无素材 | no_material | 不编造产品能力，补查或请求补充 |
| 工具失败 | tool_failure | 注入一次素材检索失败，检查是否恢复或如实结束；单元测试另覆盖生成后检查失败时保留脚本 |
| 超时修正或明确失败 | over_duration | 初稿为 44 秒，目标上限 30 秒；检查修订和重新估算 |
| 事实可追溯 | unsupported_claim | 有效素材 ID 不得为“效率提升80%”背书 |
| 有限执行 | step_limit | 限制两次工具调用，明确 incomplete |

各场景对应 `examples/inputs/`、`scripts/run_examples.py` 和 `examples/runs/{mock,glm}/`。失败注入属于工具环境，初稿属于用户输入；均显式记录，不伪装成模型自产生的错误。

首版选择受控文案，优先让事实边界可测试。自由文案生成、更强语义检索、真实配音时长测量是后续改进，不列为已实现能力。
