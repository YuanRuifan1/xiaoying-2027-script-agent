# 需求、范围和成功标准

## 用户与目标

面向短视频创作者，根据产品事实和品牌规则生成可编辑脚本，并在提交结果前检查时长、来源和产品主张。资料采用合成数据，方便评审和复现。

输入为主题、受众、平台、目标时长、风格，以及可选的用户初稿。输出包括标题、分镜、旁白或字幕、逐镜头及总预计时长、素材来源 ID、引用原文、风险与任务状态。

## 核心链路

通过 CLI 完成“模型选择动作 → 执行工具 → 观察结果 → 调整动作或结束”。模型根据实际检索结果、时长和规则反馈决定下一步；程序负责输入校验、工具执行、版本状态和调用上限。

成功脚本必须通过当前版本的时长检查和规则检查。资料不足返回 `needs_input`；工具或模型故障返回相应原因；达到执行上限返回 `incomplete`，保留已有结果。

## 验收映射

| 验收点 | 场景 | 成功标准 |
|---|---|---|
| 正常生成 | normal | 输出完整，引用有效，两项检查通过 |
| 缺关键信息 | missing | 列出缺失项，请求补充 |
| 无素材 | no_material | 依据检索结果补查或请求资料 |
| 工具失败 | tool_failure | 观察错误后重试或结束，保留已有结果 |
| 超时修订 | over_duration | 观察 44 秒初稿，修订后重新检查，或明确返回未完成 |
| 事实可追溯 | unsupported_claim | 检查具体主张与引用原文，修正无依据表述 |
| 有限执行 | step_limit | 调用触顶时停止，返回明确状态 |

输入位于 `examples/inputs/`，实际输出和 Trace 位于 `examples/runs/`。评估报告逐项链接对应记录。工具故障由测试环境注入；初稿由输入文件提供。
