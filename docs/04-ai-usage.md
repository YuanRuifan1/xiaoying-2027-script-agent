# 个人贡献与 AI 辅助记录

## 我的职责与关键决策

我负责项目的需求取舍、资源配置、复现反馈和交付推进，使用 Codex 辅助实施。具体贡献包括：

| 环节 | 我的工作与决策 | 对项目的作用 |
|---|---|---|
| 需求与范围 | 提供业务要求，选择短视频脚本方向，确认以核心 Agent 链路为交付重点 | 明确输入、输出、动态决策和验收范围 |
| 数据准备 | 选择合成的短视频编辑产品资料作为演示数据 | 确定可公开、可重复运行的数据方案 |
| 模型接入 | 提供模型访问条件，在本机配置密钥，并提出优先使用免费模型 | 使项目能够接入真实模型并控制试用成本 |
| 本地复现 | 按运行说明在 Windows 运行程序，反馈整体流程，并提供真实调用 HTTP 429 的终端截图 | 将本机实际故障带入后续改进 |
| 模型调整 | 根据复现中的限流问题，决定采用付费模型再次验证 | 推动 GLM-4.7 正常和超时修订两个场景成功完成 |
| 材料审阅 | 审阅阶段结果，提出统一项目名称、整理评估入口、集中复盘设计取舍等要求 | 使交付材料围绕项目能力和实际证据组织 |
| GitHub 交付 | 确定个人账号和公开仓库，完成官方账号授权，确认进入提交准备阶段 | 完成公开交付的账号及访问条件 |

## AI 辅助范围

使用的工具为 Codex。AI 辅助包括方案建议、代码实现与修正、测试用例编写与执行、运行记录分析、文档整理和 Git 操作。代码和测试执行由 AI 工具辅助完成，个人复现与决策见上表。

采用的技术方案和交付范围由我结合任务要求确认；遇到免费模型限流后，我基于本地反馈提出切换付费模型。两次 GLM-4.7 复测保持 Agent 代码、提示词和输入不变，正常生成 27 秒脚本，超时初稿从 44 秒修订到 26 秒。
