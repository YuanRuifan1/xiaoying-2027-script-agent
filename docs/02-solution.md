# 方案与取舍

Python 原生 Agent，无第三方运行时依赖。`providers.py` 负责智谱 HTTPS 适配和独立 Mock 策略，`agent.py` 负责上下文、工具分发与限额，`tools.py` 负责资料检索、版本化脚本及检查，`cli.py` 负责输入输出。CLI 和工具均可独立测试。

## 动态决策

模型每轮收到输入、品牌规则、历史工具结果，再选择一个函数与参数。工具白名单为 search_materials、set_script、estimate_duration、check_script、finish。模型自主生成与修订脚本，也自主决定检索改写、重试或停止。程序没有在真实模式中写“超时就替换成固定脚本”的分支。

用户初稿先交给模型保存和检查，工具返回真实计算结果后，模型决定修订。没有命中资料时，模型可以改变查询或 finish(needs_input)。工具错误与模型服务错误分别记录；HTTP 429 的自动退避只属于传输可靠性，不作为 ReAct 证据。

`MockProvider` 是固定策略，只供离线验证工程，真实模式完全不使用它。测试里的固定响应也不计为真实模型效果。

## 状态和边界

set_script 保存完整新版本并使旧检查失效。两项检查记录 SHA-256 脚本哈希。finish(completed) 必须验证最新版本的两项检查均通过；缺少来源、超时或使用过期检查均阻止成功。其他结束状态保留脚本、现有报告和原因。

缺失字段是确定性输入校验，不需要模型猜测。每次运行最多 N 次模型轮次和 N 次工具调用；非法调用也计数，普通文本不能造成无限循环。并行工具请求不执行，要求模型下轮改为单次调用。模型服务超时/失败不会回退成假成功。

## 工具计算口径

检索：对查询分词后做大小写无关的关键词匹配，返回最多三个合成文档。只有实际检索到的事实才能引用；未知来源不能通过检查。

时长：一个汉字或一个连续英文/数字词算一个发音单位。每秒 4 单位；逐镜头取 `max(旁白单位数/语速, 画面停留秒数)`，各镜头串行相加。画面与旁白同时进行，不重复相加。忽略标点停顿，不提供真实语音时长保证。

规则：产品句、文档 ID 和事实 ID 逐一核对；非事实句、标题和画面说明使用允许列表，另扫描禁用词。输出引用包含原文、位置、来源、版本。严格匹配会拒绝正确但未批准的同义改写，这个取舍写入 README，不能描述为通用语义验证。

## 为什么不用框架

此任务为单 Agent、少量本地工具。原生实现便于在有限时间内展示每一步状态，避免额外安装和框架抽象。没有重新实现生产级 Runtime、向量库、并行执行和持久化恢复；它们不是本题核心验收条件。
