# 方案设计

## 架构与技术选择

采用 Python 原生单 Agent 和 CLI，使用标准库直接接入智谱 HTTPS 接口。本地 JSON 保存产品资料和品牌规则。这个规模下，原生循环便于审阅工具调用和状态变化，也便于在干净环境复现。

| 模块 | 职责 |
|---|---|
| providers.py | GLM 接口适配、请求间隔与退避、离线策略 |
| agent.py | 模型上下文、工具调度、Trace、执行上限 |
| tools.py | 资料检索、脚本版本、时长估算、规则检查和结束校验 |
| cli.py | 参数解析、输入读取和结果导出 |

## 模型决策循环

模型每轮接收输入、品牌规则及历史工具结果，选择以下一个动作：

- `search_materials`：检索产品事实。
- `set_script`：生成或更新完整脚本。
- `estimate_duration`：估算当前脚本时长。
- `check_script`：核对来源、产品主张和品牌规则。
- `finish`：结束并给出状态和原因。

检索无结果时，模型可以改写查询或请求资料；工具失败时，模型决定重试或停止；检查未通过时，模型依据反馈调整脚本。程序不预设修订后的文案和分镜。

用户初稿由程序载入。模型先调用时长工具观察原稿，再决定修改内容。真实超时路径为：观察 44 秒 → 检索事实 → 提交修订脚本 → 估算 26 秒 → 规则检查通过 → 结束。

## 版本状态与执行上限

`set_script` 更新脚本后使旧检查失效。两项检查保存脚本 SHA-256 哈希，`finish(completed)` 核验两份报告均通过且对应当前版本。其他状态保留已有脚本、报告和终止原因。

每次运行最多 N 次模型轮次和 N 次工具调用。非法调用计入工具调用次数；普通文本响应计入模型轮次。工具逐次执行，每次结果回传模型后再决定下一步。传输层的 HTTP 429 采用最多三次有界尝试，并独立记录。

## 工具计算与规则

检索按关键词匹配合成文档，返回最多三条记录及其 ID、版本和事实。脚本按文档 ID、事实 ID 与原文逐条建立引用。

时长估算将一个汉字或一个连续英文/数字词计为一个发音单位，按每秒 4 单位计算旁白。镜头时长取 `max(旁白时长, 画面停留时间)`，再将镜头串行相加。目标时长按上限判断。

规则检查分别核对产品事实句、衔接文案、标题和画面说明，并扫描品牌禁用词。返回的问题包含镜头位置、文本和可匹配来源，供模型修订。输出引用包括事实原文、来源和版本。

## 模型与离线适配

GLM 模型通过环境变量配置，切换模型不修改 Agent 循环。真实调用记录保存在 `examples/runs/glm/` 和 `examples/runs/glm_paid/`。独立 `MockProvider` 使用固定策略验证工程流程，不作为真实模型决策证据。
